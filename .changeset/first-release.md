First release of localforce, a local Salesforce emulator for offline development and testing, published as a Docker image (`ghcr.io/samlaycock/localforce`) for linux/amd64 and linux/arm64. It speaks Salesforce's REST API and OAuth endpoints (over HTTP, and HTTPS with a generated certificate), so jsforce, simple-salesforce and go-salesforce connect to it unchanged: sObject CRUD, upsert by external id, describe, SOQL (relationship paths, subqueries, aggregates, date literals) with query paging, SOSL, sObject Collections, `/composite` (with tree, batch and graph), the Bulk APIs 2.0 and 1.0, a read-only Tooling API and the Partner SOAP calls REST has no equivalent for. Errors use Salesforce's codes and messages. The common sales and service objects are built in with their logic, and custom objects and fields come from an SFDX project (`--metadata`), `localforce.toml` or the web UI, with formula fields, roll-up summaries and validation rules evaluated. Every OAuth grant works, including authorization code with PKCE and the JWT bearer flow, with a user picker instead of a login form. A web UI browses and edits records, defines objects and fields, runs SOQL and logs every API call. The org is kept in memory, or in `--data-dir` between restarts.
